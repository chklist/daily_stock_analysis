# GitHub Actions 主动选股

`主动选股与深度分析` 工作流复用 DSA 已内置的 AlphaSift 衍生选股引擎；不需要安装独立 AlphaSift、公开 DSA API 或常驻服务器。原自选股工作流保持独立。

## 流程与默认值

北京时间工作日 18:15 触发，GitHub 排队可能延迟。使用 XSHG 交易日历，非交易日、未收盘或日历不可用时不生成当天名单。

1. `balanced_alpha` 规则、因子及本地 scorecard 排序，开启高风险否决，先取前 18 只候选，不调用 LLM；补全行业和题材后重新排序，同一大类最多 1 只、合计最多 3 只进入 DSA。
2. 全市场快照少于 1000 条、无来源或仅有旧缓存时失败；逐只校验日线必须到最近完整交易日，不接纳过期日线缓存。
3. 候选代码显式传给 `StockAnalysisPipeline`，沿用现有模型、Sub2API Responses 配置及 Anspire 新闻搜索。空候选不会回退到 `STOCK_LIST`。
4. DSA 评分至少 60、动作 buy/add（旧结果兼容买入/加仓/增持/强烈买入）、非低置信度且本轮新闻检索有结果，才进入观察名单。这是初始工程筛选规则，未经收益回测验证；分数不是胜率。
5. 一次汇总推送到既有 Telegram。没有合格股票会明确说明。模型失败、行情校验失败或发送失败会使任务失败并保留诊断，避免误报成功。

入选理由、筛选来源、行情日期和完整 DSA 复核结果保存在 `reports/proactive/`；Actions artifact 保留 30 天。脚本不自动下单。尚未添加跨次任务的候选去重或 T+N 自动评估；下载结果可供后续研究，不能据此宣称已验证选股收益。

## 配置与运行

工作流复用仓库 `LLM_CHANNELS`、`LITELLM_MODEL`、`LLM_PRIMARY_*` Variables/Secrets，以及 `ANSPIRE_API_KEYS`、`TELEGRAM_BOT_TOKEN`、`TELEGRAM_CHAT_ID` Secrets；与当前已验证的 primary 渠道一致。密钥不写进代码。可选 `TICKFLOW_API_KEY` 仓库 Secret 同时供每日分析和主动选股的 DSA 复核使用，支持 `TICKFLOW_PRIORITY`、`TICKFLOW_KLINE_ADJUST`、`TICKFLOW_BATCH_DAILY_ENABLED` 和 `TICKFLOW_BATCH_SIZE` 参数；不改变独立初筛快照来源与资金流采集路径。

Actions → 主动选股与深度分析 → Run workflow：

- `strategy`：均衡多因子、质量价值或双低策略。
- `force_run`：仅用于非交易日/收盘前验证，不伪造当天行情日期。
- `screen_only`：只验证候选和行情，不调用模型，也不发送消息。
- `notify`：完整分析后是否推送；定时运行默认推送。

本地入口：

```bash
python scripts/run_proactive_screening.py --screen-only
python scripts/run_proactive_screening.py --strategy balanced_alpha --top 3 --min-score 60 --notify
python -m unittest discover -s scripts/tests -p test_proactive_screening.py -v
```

脚本参数不会改写 `.env`；沿用现有配置。若要修改默认数量或分数，请调整工作流参数，数量限制为 1–3。推送仅包含通过复核的详细报告，未通过者列出排除原因。

## 限制与回滚

### 资金流采集诊断

每日分析和主动选股工作流默认使用 `FUNDAMENTAL_STAGE_TIMEOUT_SECONDS=45`、
`FUNDAMENTAL_FETCH_TIMEOUT_SECONDS=15`，可通过同名 Actions Variables 覆盖。
它们分别表示聚合总预算和单个采集任务预算；本地/Docker 默认值仍为 8 秒。
A 股个股资金流先执行，避免财务接口耗尽预算；普通分析仅采集个股资金，
不等待可选板块资金流。独立资金流工具仍保留板块查询能力。

资金流调用明确传入股票代码和 sh/sz/bj 市场，按日期取最新主力净额（元），
5/10 日值仅在有足够有效历史记录时求和。不会用排名、占比或默认股票数据替代。
来源、耗时、错误类型写入 `[capital_flow]` 日志；主动选股 JSON 额外保留
`capital_flow_diagnostics`，包括实际数据日期。接口中断仍可能造成缺失，
修复不保证第三方接口可用，也不移除买入降级规则。

Actions → `资金流采集诊断` → Run workflow 可独立验证沪深样本，
不调用模型、不发送通知。该工作流先跑回归测试，再调用生产基本面聚合入口，
只有两个样本都取得最近完整交易日的资金净额才成功；记录保留 14 天。
本地运行：`python scripts/diagnose_capital_flow.py --stocks 601328,000001`。
若接口不可用，查看 artifact 中的 `capital-flow-check.json`，不要仅提高超时后认定恢复。

资金流改动可通过撤销对应修复提交回滚；原有密钥、通知设置和评分门槛均不需修改。

第三方实时快照不保证每行都携带交易日；本流程拒绝旧缓存并验证候选日线日期，但不等于独立审计全部实时字段。行业未知时排除候选，题材缺失或过期时不计分；部分题材覆盖不等于完整市场热点分析。实时源和模型仍可能超时，45 分钟作业上限负责最终中止。

关闭此工作流即可停止新增选股推送，不影响原 `每日股票分析`。撤销引入本工作流和脚本的提交可回滚代码；不删除原 Secrets、报告或数据库。

本文为该 fork 的中文运维说明，不修改上游中英文产品首页；未新增英文副本。

## 行业与题材增强

- 每轮优先查询 TickFlow 申万一级行业；权限不足、超时或缺失时，回退 efinance 东方财富基础资料。分类每轮刷新，不使用过期行业缓存。
- 复用策略的大类映射：银行与保险归入金融；大类限制为硬上限。行业未知无法验证分散度，直接排除；不足 3 只时不凑数。
- 个股所属板块与概念目录交叉验证，避免把地区板块误认作题材。概念按名称排序后在候选之间轮询，最多查 24 个不同概念的日线；这是一项有预算的部分覆盖，不声称找到了全部热门题材。
- 只有概念日线最新日期等于最近完整交易日才有效。热度为 `clip(50 + 10 × 当日涨跌幅, 0, 100)`，个股取有效概念均值；缺失/过期为 0。先移除原中性题材分，再按策略归一化权重加入真实题材分；均衡策略该权重为 5%，其余因子和风险否决保留。
- 元数据总预算 180 秒，单项查询有超时；错误只记录类型，避免泄漏带密钥的 URL。`industry_theme` 保存全部候选的来源、有效日期、覆盖数、调整前后分数、大类及排除原因；`metadata_diagnostics` 保存接口状态与耗时。
- 修改主动选股代码时，push 自动执行单元测试和 `--force-run --screen-only` 在线校验，不调用模型、不推送。假期使用最近完整交易日。
- 回归测试：`python -m unittest discover -s scripts/tests -p 'test_proactive*.py' -v`。

### 题材接口可靠性

题材归属优先使用东方财富 F10 数据中心 `RPT_F10_CORETHEME_BOARDTYPE`，按本轮候选批量查询，不依赖全市场概念目录。仅接受股票代码匹配、`IS_PRECISE=1`、有效 BK 板块代码且有归属说明的记录，排除明确标记为行业/地域板块的条目。归属说明可引用历史报告，只用于证明分类，不作为近期新闻或热度。批量失败时才回退原目录/归属路径。

日志分别输出 `concepts`（有题材归属的股票数）和 `heat`（取得日期有效板块指数热度的股票数）。报告展示题材名称，JSON 保存代码及原始归属说明。按用户要求，只接受板块指数行情，绝不以成分股涨跌幅估算替代；指数缺失时题材分仍为零，归属恢复不等于热度恢复。

目录查询使用独立子进程，东方财富预算 45 秒、同花顺备用预算 30 秒；归属查询 12 秒、指数历史 15 秒，均受元数据总预算 180 秒约束。子进程超时后终止并等待退出，再进行后续查询，避免遗留线程与回退请求重叠。不增加外层重试；目录失败立即冷却，归属同一接口连续失败两次后冷却 30 分钟。指数失败仅冷却该提供商的具体板块和交易日 30 分钟，不阻断其他板块；忽略旧版本的整个指数接口冷却标记，继续复用日期有效的成功缓存。库内部仍可能重试，但不会超出子进程总期限。

`.cache/proactive-metadata` 保存目录 7 天、个股板块归属 3 天；指数历史缓存按起止交易日期区分、最长保留 24 小时，写入与计分前都验证最新完整交易日。缓存过期、未来时间戳或文件损坏时重新采集；缺失/过期热度仍为零。Actions 使用独立缓存恢复/保存步骤，使新 runner 可以复用成功数据和短期失败冷却。修改缓存版本前缀可强制重新构建。

东方财富目录失败后尝试同花顺目录；东方财富指数历史失败后，仅对同花顺目录中名称完全一致的题材尝试其指数历史，明确记录 `ths_heat` 来源。同花顺涨跌幅由相邻有效收盘价计算，其指数成分和口径可能与东方财富不同。股票归属仍来自东方财富，与备用目录按精确名称关联，不混用两家板块代码、不模糊匹配；若归属也不可用且无有效缓存，不能靠备用目录推断股票题材。东方财富指数查询直接传已缓存的板块代码，避免每只题材重复请求完整目录。

诊断状态包括 `cache_hit`、`TimeoutKilled`、`cooldown`、`budget_exhausted` 和 `StaleOrInvalidHeat`。独立探测与正式筛选复用缓存；在线验证成功不代表全部题材源均可用，应同时查看实际覆盖率。本改动只调整主动选股元数据采集，不更改其他模块的全市场行情采集实现。

指数诊断包含具体 symbol 和 data_date；unique_index_coverage 表示成功指数数/全部待查指数数，与 heat 的股票覆盖数分开。每只股票的 missing_index_themes 列出尚无有效指数的题材，可结合逐板块诊断区分请求失败、冷却、预算耗尽及过期。

### 完整分析可靠性修复

主动选股工作流设置 `LLM_STREAM_ENABLED=false`，模型以非流式返回，避免中途断流后整段重新生成；其他入口默认仍开启流式。Telegram 转换会转义策略名和诊断标签中的下划线，同时保留链接。

行业涨跌榜在同一 DataFetcherManager 内合并并发请求，成功缓存 300 秒、空结果缓存 30 秒，并返回独立副本；缓存只服务深度分析的市场上下文，不替代主动筛选按交易日校验的板块指数。资金流为空时明确标记 failed，不能标作部分成功。

东方财富板块日线与个股资金流复用有界官方历史请求：校验返回代码、市场和字段结构，仅使用净额列；在总请求预算 10 秒内尝试主节点与 91 节点。如果检测到环境代理，允许该公开行情请求尝试独立直连 Session，证书验证仍开启，不修改系统代理或其他服务。底层依赖的全局请求补丁仍可能增加开销，板块查询外层子进程继续负责强制限时。接口错误仅记录异常类型。

同花顺目录仅读取官方板块页的概念导航，不再附带抓取全市场分页摘要；通过目录提供的板块 ID 获取实际指数 ID 和年度日线，再计算相邻收盘涨跌幅。只接受名称完全一致且最新日期有效的结果，不推测代码或合成指数。修改采集实现会更新失败冷却版本，保留日期有效的东方财富成功缓存。

## 东财故障隔离

- efinance 调用复用 AKShare 的 spawn 子进程边界，超过原有调用超时后终止并回收进程；不再遗留继续请求的后台线程。
- 已接入子进程的东财历史接口在同一主进程共享熔断状态；历史、资金流、报价、归属及基本信息通道分开。连续两次网络/超时/403/429/5xx 故障后冷却 60 秒，成功后复位。无效股票或字段校验失败不触发全通道熔断。
- 子进程内东财 HTTPAdapter 重试关闭；同一路径连续两次网络故障后停止实际请求，外层第三方库的重试仍受子进程硬超时限制。单次网络等待不超过剩余预算及连接/读取各 3 秒；TLS 校验和代理设置保持原样。
- 资金流及板块历史请求继续使用原有有限主机回退，错误记录区分 proxy_error、tls_error、timeout、connection_error、http_*、invalid_payload 和 circuit_open。
- 熔断不跨 Actions 运行或独立进程共享。初筛的独立板块工作进程仍使用现有持久缓存/失败冷却；此改动没有全局替换所有 AKShare 接口，也不保证东财数据恢复。
- 可选 ENABLE_EASTMONEY_PATCH 仍默认关闭；仅修复失败缓存及并发复查，不自动启用授权补丁。
- 不更改股票评分、缺失数据处理或数据源优先级；题材仍只接受日期有效的真实板块指数。
